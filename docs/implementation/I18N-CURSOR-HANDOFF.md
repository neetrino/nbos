# Передача реализации Cursor

Это инструкция исполнения для AI, не продуктовый канон. Код ещё не реализован. Открыть новый чат Cursor в этом репозитории, выбрать Grok 4.6 High и передать стартовый промпт ниже. Возможность назначения Composer субагенту подтверждена владельцем; повторно исследовать её не требуется.

## Стартовый промпт

```text
Реализуй первый релиз мультиязычности NBOS по docs/implementation/I18N-IMPLEMENTATION-PLAN.md, этапы 0–5. Продуктовые решения уже зафиксированы в docs/NBOS/01-Platform-Overview/07-Interface-Localization.md, TECH_CARD и архитектуре. Прочитай AGENTS.md и применимые правила/skills. Прочитай также всю инструкцию docs/implementation/I18N-CURSOR-HANDOFF.md.

Ты — Grok 4.6 High, основной исполнитель и проверяющий. Сам реализуй и проверь архитектурную основу, сохранение языка, SSR/BFF/cache и один эталон перевода. Затем назначай Composer (обычный, не Fast) субагентом для переноса UI-строк, русского перевода по глоссарию и подключения переводов по эталону. Я подтверждаю, что ты можешь назначать Composer субагентам. Не трать время на повторную проверку этой возможности.

Выполни этапы последовательно до готового проверенного EN/RU релиза в рабочем дереве. Сначала сделай coverage и baseline. Не останавливайся после одного плана или отчёта субагента. Сам проверяй diff, исправляй ошибки, запускай необходимые проверки и обновляй журнал после каждого этапа. Массовую работу делегируй только после проверки эталона. Не делегируй Composer архитектурные решения и окончательную приёмку.

Текущий scope: общая навигация desktop/mobile, меню аккаунта/темы/языка, главный Dashboard со всеми его состояниями и четыре формы создания Task/Meeting/Lead/Expense. Детальные границы и исключения — в каноне. Остальные модули и HY — последующие этапы, не расширяй поручение автоматически.

Не меняй бизнес-логику, права, валюты, часовые пояса, URL и сохранённые идентификаторы ради перевода. Не переводи пользовательские данные. Сохрани чужие изменения. Не делай commit/push, production deployment/migration, db push/reset и удаление данных. Подготовь additive migration в репозитории; применение только к подтверждённой изолированной dev/test БД по migration skill.

Работай автономно в рамках плана. При настоящем конфликте продуктовых решений или недоступной обязательной инфраструктуре зафиксируй конкретный блокер и продолжай независимые части. Не выдавай непроверенное за готовое. В конце дай перечень завершённых этапов, проверок с результатами, оставшегося scope и ограничений. Production rollout не входит в поручение.
```

## Делегирование и бюджет

- Основной агент: Grok 4.6 High. Субагент массовой работы: Composer обычного режима; назначать явно, не inherit и не Auto. Не подменять недоступный Composer более дорогой моделью молча.
- Сначала один проверенный эталон. Затем 1–2 Composer одновременно для независимых пакетов; не дробить каждую строку в отдельное поручение.
- Grok владеет зависимостями/lockfile, shared contracts, root providers, backend, схемой/миграцией, общей обработкой ошибок и интеграцией.
- Composer получает явные файлы, namespace и разрешённые изменения. Один файл/каталог словаря — один текущий владелец. Никакой одновременной перезаписи common-каталога разными агентами.
- Каждое поручение содержит ссылки на канон/глоссарий, образец, список файлов, запреты, критерии проверки и формат отчёта. Не рассчитывать на наследование всего контекста родителя.
- Отчёт Composer: изменённые файлы, добавленные ключи, спорные термины, выполненные проверки и пропуски. Grok проверяет код и смысл перевода, а не только резюме.
- Передавать контекст конкретного участка, не заставлять каждого субагента повторно анализировать весь monorepo. Не оценивать стоимость по числу строк: учитывать повторные запуски и правки.
- Для возобновления после смены чата читать журнал плана и coverage, проверять рабочее дерево; не начинать миграцию заново и не считать прошлый отчёт доказательством без результатов.

