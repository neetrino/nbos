# Ревизия видов продукта в Core (2026-09-24)

## Что есть сейчас

После уточнения владельца `Core` показывает 41 доступный для нового продукта вид: 34 направления Code, 6 видов Marketing и `OTHER`. Среди Code теперь 12 видов сайтов. У пяти новых направлений сид создаёт только **черновик состава**, без units и цены продажи. Пока владелец не настроит и не опубликует их, система не предлагает по ним цену или бонус. `MOBILE_APP` и `SAAS` остаются только для старых карточек и в новом выборе скрыты. Виды WordPress и Shopify используют те же значения, что и Code; отдельные ядра по стеку не создаются. Платформа WEB / APP / DESKTOP — отдельный признак, не вид и не ось расчёта. Источники: решения 1.23 и 1.25, `packages/shared/src/constants/product-types.ts`, `scripts/delivery-profiles/delivery-profiles-seed-data.ts`.

## Решение по составу

- **Оставить** существующие 29 направлений Code. Коды уже связаны с опубликованными нормами и историческими карточками, поэтому их не переименовываем и не удаляем.
- **Добавить** пять отдельных WEB-видов: `REAL_ESTATE_WEBSITE`, `SERVICE_WEBSITE`, `TRAVEL_WEBSITE`, `CLASSIFIEDS_PORTAL`, `JOB_BOARD`. У всех разные обязательные составы ядра. WordPress предлагает первые три, Code — все пять. Shopify остаётся только магазином.
- **Оставить** 6 направлений Marketing и `OTHER` в общем выборе продукта. Они не являются типами сайтов; пустая карточка Core означает, что норма для неё не задана. Ревизия бонусных норм Marketing — отдельный вопрос, без автоматического переноса норм Code.
- **Не добавлять** дополнительные отраслевые названия только ради полноты списка. Например, ресторан или клиника могут использовать «Сайт услуг», если обязательная основа совпадает. Функции онлайн-записи и оплаты выбираются отдельно.
- **Не переносить** units и цены соседних ядер на новые виды. Черновики новых ядер содержат состав и именованные комплекты, но пустой вектор ролей: публикация блокируется до настройки норм владельцем. Опубликованные версии старых ядер и исторические сделки остаются прежними.

| Запрос клиента                                          | Текущее ядро                   | Когда менять выбор                                                                                                     |
| ------------------------------------------------------- | ------------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| Одна страница с заявкой                                 | Лендинг                        | Если нужны разделы и редактор контента — сайт компании                                                                 |
| Сайт о специалисте или небольшой компании               | Сайт-визитка                   | Если нужны регулярные разделы услуг, кейсы и новости — сайт компании                                                   |
| Сайт услуг, клиники, агентства, ресторана               | Сайт услуг                     | Онлайн-запись и оплата добавляются функциями; сайт о самой компании остаётся «Сайт компании»                           |
| Портфолио, проекты, галерея                             | Сайт-визитка или сайт компании | Галерея и кейсы — функции, не новый вид ядра                                                                           |
| Объекты недвижимости с агентами и заявками              | Сайт недвижимости              | CRM агентства, онлайн-запись на просмотр и оплата добавляются отдельно                                                 |
| Туры, направления и программы поездок                   | Туристический сайт             | Живое бронирование мест и оплата добавляются отдельно                                                                  |

| Новости с редакцией                                     | Новостной сайт / медиа         | Личный журнал или авторская лента — блог                                                                               |
| Сайт конференции или фестиваля                          | Сайт мероприятия               | Билеты, регистрация и операционное управление — отдельные виды или функции по объёму работ                             |

## Изменение интерфейса

Подписи видов раскрыты в Core, CRM и форме Product на RU / EN / HY. Карточка Core показывает описание вида, а поиск находит вид по названию, описанию и коду. Для пяти новых видов добавлены значения enum, варианты выбора и черновики состава без финансовых значений.

## Миграция и публикация

Миграция аддитивная: пять значений PostgreSQL enum и пять новых активных опций системного списка. Существующие строки не обновляются и не удаляются. Риск низкий для данных, но нужна согласованная последовательность: применить миграцию в разрешённой среде, развернуть API и web с новым enum, затем отдельно создать черновики через `pnpm seed:delivery-profiles --apply`. Production migration и публикация норм — отдельные действия владельца. Если выпуск нужно откатить, новые опции можно скрыть через `is_active=false` и вернуть прежний код; значения enum оставляют для совместимости с уже созданными записями.
