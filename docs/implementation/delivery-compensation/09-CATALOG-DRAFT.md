# Черновик каталога: ядра и модули

Источник решений: [`07-OWNER-DISCUSSION.md`](./07-OWNER-DISCUSSION.md) и [`08-CONSTRUCTOR-AND-SIZING.md`](./08-CONSTRUCTOR-AND-SIZING.md).
Статус: **черновик исполнителя для правки владельцем**. Ничего не залито в базу.

**Units здесь сознательно не проставлены.** Владелец публикует их через админку норм, когда она будет готова. Здесь только состав, структура и градации.

## Как читать

- **Ядро** — неделимый блок вида продукта. Отключить и вычесть нельзя, состав одинаков на всех уровнях размера, цена ядра имеет градацию по числу выбранных модулей.
- **Модуль** — карточка каталога, оплачивается отдельно. У части модулей есть **градации** (маленький / средний / большой или по объёму); выбирается одна.
- **Пресет** — набор модулей, заранее отмеченный для уровня размера. Не делает модули бесплатными.

## Объём первой волны (выбор исполнителя)

Полная раскладка: **магазин**, **сайт компании**, **лендинг**, **CRM**. Это основной поток.
Только ядро, без глубокой раскладки: **мобильное приложение** — направление новое и растущее, ядро назвать нужно, а модули у него в основном те же.
Остальные виды (маркетплейс, бронирование, LMS, ERP, SaaS, недвижимость, туризм, билеты, вакансии, медиа, интранет, desktop) получают ядро и несколько модулей по мере первых сделок.

## Ядра

### Ядро магазина

Главная, каталог с категориями, страница товара, корзина, checkout, My Account покупателя, поиск, небольшая админка (товары, категории, заказы), базовые страницы (о нас, контакты, доставка и оплата), формы обратной связи, адаптивность, базовое SEO (метаданные, sitemap, robots), подключение аналитики.

### Ядро сайта компании

Главная, внутренние страницы (услуги, о компании, контакты), новости или блог в минимальном виде, формы обратной связи, админка контента, поиск по сайту, адаптивность, базовое SEO, аналитика.

### Ядро лендинга

Одна страница с секциями, форма заявки, адаптивность, базовое SEO, аналитика.
**Важно:** админки, личного кабинета и мультиязычности в ядре лендинга нет — всё это отдельные модули (решение владельца).

### Ядро CRM

Сущности клиент, компания, сделка; карточка записи; этапы и воронка; список и фильтры; сотрудники, роли и права; главный админ; журнал активности; базовые отчёты. Аккаунтов внешних покупателей нет.

### Ядро мобильного приложения

Каркас приложения, навигация, авторизация, экраны списка и детали, профиль пользователя, push-инфраструктура на уровне каркаса, сборка и публикация в один магазин приложений.

## Пресеты (скелет)

Количество модулей в пресете — ориентир владельца: минимальный около 10, классический около 15, большой около 20, самый большой около 30. Состав правит владелец; ниже логика отбора, а не окончательные списки.

| Уровень    | Логика отбора                                                                             |
| ---------- | ----------------------------------------------------------------------------------------- |
| SMALL      | Ядро плюс одна оплата, базовые уведомления, минимальный импорт                            |
| CLASSIC    | Плюс мультиязычность, купоны, отзывы, доставка, вторая оплата                             |
| LARGE      | Плюс бонусы, кошелёк, склад, умный поиск, расширенные уведомления, интеграции             |
| VERY_LARGE | Плюс B2B-прайсы, мультискладность, отчёты, маркетплейсы, API                              |
| ENTERPRISE | Плюс многофилиальность, SSO, производительность, task management, полный набор интеграций |

## Что осталось незаполненным

1. Units всех ядер и модулей — публикует владелец через админку норм.
2. Точные списки пресетов по каждому виду.
3. Состав ядра как структурированный список в схеме (сейчас у профиля только `description`).
4. Градации: конкретные уровни у бонусной программы, поиска, админки, отчётов, уведомлений.
5. Зависимости между модулями (например task management требует роли и права) — предупреждением, этап 2+.
6. Разовые услуги вроде съёмки и заполнения товарами — пункт 12 в [`07`](./07-OWNER-DISCUSSION.md), обсуждается последним.
