# Регистрация продукта без разработки

**Accepted — 2026-10-02.** Решение заказчика в обсуждении регистрации готовых клиентских продуктов. В пределах создания Product, его присутствия на Delivery Board и Hub это дополнение имеет приоритет над прежней формулировкой «каждый Product — delivery-сущность».

## Бизнес-правила

- Product всегда принадлежит Project. Product может существовать без нашей разработки.
- Варианты создания: готовый продукт **без разработки** (default общей формы) или новый продукт **с запуском разработки**. Обычный PRODUCT Deal → Won сохраняет существующий handoff.
- Для готового продукта не создаются Order, delivery checklist, события сдачи или delivery-бонусы. `deliveryEnabled = false`, `deliveryStage = null`, `deliveryResolution = null`. Это не Done и не Cancelled.
- Такой продукт доступен в общем каталоге и в Project, но отсутствует во всех представлениях Delivery Board, включая Closed. В каталоге его view — `registered`, подпись «Без разработки». При действующей maintenance-подписке view — `maintenance`.
- Проект с зарегистрированным продуктом остаётся Active; отсутствие разработки не закрывает проект.
- Extension к готовому продукту проходит собственный Delivery после Won. Maintenance определяется подпиской; никаких дополнительных maintenance-флагов на Product.
- Регистрация сама по себе не запускает подписку, выставление счетов, создание WhatsApp-группы или коммерческую сделку.

## Единая форма

Доступна из Product picker в Deals (Extension / Maintenance / применимые Outsource), Subscriptions, Bills / Invoices, Client Services, а также Project → Products.

1. Название продукта.
2. Классификация и зависимые параметры в одной адаптивной строке.
3. Основной контакт (поиск / создание); при выборе существующего проекта подставляется его основной контакт, если пользователь ещё не выбрал свой.
4. Project: общий outlined-блок с подписью в обводке. Слева полноценная кнопка «Создать» + название, справа более широкий стандартный поиск; ориентир 30/70.
5. Company: такой же блок, связь необязательна при регистрации. В контексте Tax компанию можно создать сейчас; существующие требования реквизитов при выставлении Tax Invoice сохраняются.
6. «Отмена» / «Создать и выбрать».

Без повторного заголовка «Проект и компания», разделителя, поясняющего или итогового текста. Названия нового Project и Company равны Product.name. Это подстановка при создании, не последующая синхронизация переименований.

Создание и поиск всегда доступны. Поиск не сбрасывает создание до выбора найденной записи. Выбор существующего объекта снимает создание; выбор «Создать» очищает ранее выбранный объект. Если Project уже известен из контекста — он подставлен; иначе выбран новый Project. Company подставляется из выбранного Project только до явного выбора пользователем.

Общая кнопка сохраняет Product + недостающие Project / Company в одной транзакции. Отмена ничего не создаёт. Ошибка вставки откатывает связанные новые объекты. После сохранения Product выбран в исходном поле; несохранённая исходная форма сохраняет свой ввод. Отдельно созданный из контактов Contact остаётся самостоятельной записью справочника.

## Контакты и доступ

- Для регистрации обязательны основной Contact и выбранный/новый Project.
- Новый контакт продукта добавляется к контактам существующего Project по принятому канону Contact ↔ Product, не заменяя основной контакт проекта.
- Регистрация требует PROJECTS.ADD. Создание Company дополнительно требует CLIENTS.ADD. Сервер проверяет права до записи.
- Связи разрешены только с активными Project, Contact, Company.
- Delivery-команды для Product с `deliveryEnabled = false` отклоняются сервером.

## Техническое изменение

Добавлено `products.delivery_enabled BOOLEAN NOT NULL DEFAULT true`. Старые продукты сохраняют поведение. Регистрация доступна через `POST /projects/products/register`; существующий endpoint создания / Won не меняет defaults. Extension не наследует запрет разработки родительского продукта.
